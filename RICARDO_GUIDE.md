## The One Rule

> If you can't explain the code in your own words, you haven't learned it yet.

You CAN use AI. AI is a great tutor and debugger.

But if you copy code and paste it without understanding it, you haven't learned anything. You've just tricked yourself.

The test is simple: **Can you explain what this code does to someone else?**

If yes — you own it.

If no — go back and learn it.

Read `RESOURCES/ai_policy.md` for examples of good and bad AI use.

## What to Do When You're Stuck

You WILL get stuck. Every programmer gets stuck. Getting unstuck is literally the main skill.

Here's your system:

1. Read the error message out loud. Seriously, read it word by word.
2. Search the error message online.
3. Ask AI to help explain the error (not just fix it).
4. Try at least one solution.
5. Document what you tried in your journal.
6. If you've done all that and still stuck → check `CHECKLISTS/before_asking_dad.md`

More detail: `TROUBLESHOOTING/README.md`

## Your Engineering Journal

Every week, you write a short entry in `JOURNAL/`. Not an essay. Just:

- What did you build?
- What was the hardest part?
- What did you figure out?
- What do you want to build next?

This takes 10 minutes. But when you look back at week 1 from week 10, you'll be amazed at how far you've come.

## Friday Demo Videos

Every Friday (or whenever you finish a project), record a short 2–5 minute video showing:

- What you built
- How it works
- One thing you learned

You don't need to be polished. Just show it. Talk through it. This forces you to understand what you built — and it builds your portfolio.
