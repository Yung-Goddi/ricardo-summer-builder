That feeling is what programming is about.

## Why Hardware First?

Three reasons:

1. **Immediate feedback** — Code runs, something physical happens. No waiting, no wondering.
2. **Confidence** — Even simple programs feel impressive when there's a blinking light involved.
3. **Understanding** — Controlling real things teaches you why code matters.

## Before You Start Each Project

1. Read the whole README before touching any code
2. Look at the wiring diagram before connecting anything
3. Understand what the project is supposed to do
4. Then build it

Don't skip the reading. Five minutes of reading saves 30 minutes of debugging.

## The Rhythm of a Project

**Session 1:** Set up the wiring. Get the basic code running. Make the LED blink or the sensor read.

**Session 2:** Improve it. Add features. Make it more useful or more fun.

**After each project:** Push your code to GitHub. Take a photo of your hardware setup. Write a quick journal entry.

---

## Hardware Safety Rules

1. **Always disconnect USB before rewiring.** Don't change wires while it's powered.
2. **Double-check polarity.** LEDs have a long leg (+) and short leg (-). Wrong way = nothing works.
3. **Resistors are not optional.** They protect LEDs from burning out. Always use them.
4. **GND before VCC.** Connect ground first, power second.

---

## When Your Code Doesn't Work

This happens to everyone. Even professionals.

1. Check the wiring first (most problems are wiring, not code)
2. Read the error message in Mu
3. Check: did you save and flash the new code?
4. Try simplifying — comment out parts until you find what's broken
5. Search the error message online
6. Check `TROUBLESHOOTING/common_errors.md`
